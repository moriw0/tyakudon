# Google Maps を UI から廃止する

v1 は近くの店舗探し（`home#search`）と店舗詳細（`ramen_shops#show`）で Google Maps JavaScript API の地図を埋め込んでいた。v2 ではこれを廃止し、**地図を一切表示しない**。現在地から店舗を探す導線は、Geolocation API で緯度経度を取得して `ramen_shops#near_shops` の距離順テーブルに遷移する形に置き換えた。店舗詳細の地図は外部地図サービスへのテキストリンクだけにした。

## なぜ

- v2 の設計方針は「ブラウザのデフォルトスタイルを最大限活用し、外部依存を持たない」こと。地図は方針に対する最大の例外で、外部 JS・API キー・ローディングスピナー・専用 CSS をすべて引き連れてくる。
- 待ち時間を知りたいユーザーにとって、意思決定に必要なのは店舗名と待ち時間の比較であって地理的な位置関係ではない。距離順に並んだテーブルで用が足りる。
- 地図の描画完了を待つ設計だったため、`map_controller.js` の `map-loaded@window` イベント待ちやスピナー表示といった状態管理が必要だった。テーブルに置き換えるとこれが全部なくなる。

## 誤解しやすい点

**サーバー側の Geocoder は残る。** `geocoder` gem は店舗の住所から緯度経度を求めるために使っており、`near_shops` の距離計算がこれに依存している。廃止したのはクライアント側の地図描画だけで、位置情報そのものは v2 でも中核機能である。

`config/initializers/geocoder.rb` を見て「地図を使っているのでは」と読み違えないこと。

## 戻すコスト

地図ベースの UI に戻すのは大工事になる。Google Maps JS API の読み込み、API キー管理、`map_controller.js` 相当の Stimulus コントローラー、マーカーとインフォウィンドウの描画、レスポンシブ対応をすべて作り直すことになる。地図を再導入するなら、この ADR を supersede する形で「なぜ方針を変えたか」を書き足すこと。
